# guardAI 案例库（docs/cases）

"规则 = AI 判断的缓存"。本目录沉淀 AI 审查抓到的真实缺陷案例，供三类消费方使用：

1. **AI 规则发现员**（AI 层第三步）：从案例中批量提炼新规则 → 人工确认 → 沉淀进规则资产（免费执法）；
2. **AI 审查员**：作为 review 提示词的正反例素材，提升语义审查命中率；
3. **人工/新成员**：了解 AI 写代码的高频踩坑面，反哺规范与提示词。

## 目录结构

| 文件 | 说明 |
|---|---|
| `ai-review-11rounds.md` | 首批案例库正文：十一轮自审闭环 43 条 findings（warn 19 / info 24），按 7 大类归档，每条含问题/根因/修复/**可沉淀规则+目标层** |
| `raw/` | 原始 review JSON 报告（11 份，证据链，machine-readable） |

## 案例条目格式

```
#### C{编号} · {级别} · R{轮次}-{序号}
位置 / 问题 / 根因 / 修复 / 可沉淀规则 → 目标层
```

目标层取值：【本地检查】= 引擎可确定性查（分析器/CI 门禁）；【AI 审查清单】= 语义类、进 review 提示词检查项；【提示词规则】= 进 AGENTS.md/装配注入的写作约定。

## 可沉淀规则汇总（43 条案例 → 32 条去重规则）

### → 本地检查（引擎可查，12 条优先沉淀）

1. 送外部服务前必须过敏感过滤（文件名+目录+内容特征），命中只报文件名不发内容（C22）
2. 浮点范围校验必须先 `IsFinite` 再比大小（C39）
3. Regex 必须静态 readonly + Compiled，禁止方法内新建（C28）
4. 子进程输出必须 stdout/stderr 并发消费（C04）
5. async 方法禁止 `GetAwaiter().GetResult()`，耗时调用必须收 CancellationToken（C16/C25）
6. 可变数组不得作为"常量集合"暴露，用 IReadOnlyList（C40）
7. 一文件一公共类型，文件名=类型名（C15/C30）
8. 局部变量/参数 camelCase（C01）
9. 配置键/段名单点引用，禁止魔法字符串；"按名取配置"必须有测试锁（C02）
10. 默认值单点定义（常量类），配置解析与类型构造同源（C10）
11. 枚举/等级语义禁止魔法数字（C07）；级别映射单点（C06）
12. public API 枚举式入参显式拒绝非法值 + 校验单点 + 异常契约一致（C32/C33）

### → AI 审查清单（语义类，进 review 提示词）

- 异常契约：方法只抛注释声明的异常；第三方异常边界转换（C13/C37/C38）；可控分支不暴露堆栈（C23）
- 报错准确性：报错指向真实原因、区分缺失/格式错（C31）；区分成因、随报错输出跳过清单（C42）
- 取消语义：用户取消 vs 超时按 CancellationToken 分流（C17）；事件订阅成对注销（C43）
- 复用/职责：共用工具独立静态类（C05/C36）；工具方法合并（C19）；序列化嵌套递归（C03）；JsonSerializerOptions 共享（C18）
- 分层/注释：依赖方向单向（C21）；注释=实际行为、数值与常量一致、改值必改注释、重构同步注释（C09/C24/C29/C34/C41）；未用引用清理（C14）；类名覆盖职责（C35）；热路径不重复物化（C27）；catch 不列基类+派生类（C08）

### → 提示词规则（写作约定，进 AGENTS.md）

- 两字母缩写全大写（AI/IO/HTTP），品牌名按官方写法（C11/C20）
- `--json`/机器可读输出 stdout 纯协议数据，人类提示走 stderr（C12）
- 一条业务策略只允许一个定义点（C26）
- 安全边界意识：送审/外发先过滤（C22）
- 浮点校验先 IsFinite（C39，与本地检查双保险）

## 维护约定

- 新案例沿用 `C{连续编号}`，正文追加到对应类别小节，并在本 README 规则汇总中登记新提炼的规则；
- `raw/` 只进不出（append-only），作为案例的证据链；
- 案例经"AI 发现 → 人工确认 → 沉淀规则"后，规则进入规则资产由引擎免费执法，案例保留作溯源。
